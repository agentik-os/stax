# U-038: the console pattern table — stop improvising screens the framework proves

TARGET: {{TARGET}}
REFERENCE: DESIGN-SPEC.md "The console and analytics patterns" + `stax-migrate patterns`

## DETECT
- The conversion doctrine teaches UI PRIMITIVES (modal -> panel, tabs -> drills,
  grid -> .dt, select -> segments) and stops there. Grep the spec for the screens
  a real SaaS admin ships: API key, secret, invoice, quota, rate limit, service
  health, status page, log stream, invitation, member, environment, feature flag,
  webhook, cohort, retention, projection. If they return ZERO, a migrating agent
  has to invent each of those screens from scratch.
- Meanwhile the reference app already implements them. The knowledge exists and
  is unreachable: nothing in the doctrine points at it.

## APPLY
1. THE SECOND TABLE: beside the primitive table, a "console and analytics
   patterns" table whose LEFT column is what the source app calls the screen and
   whose RIGHT column is the panel type, the grammar that makes it Stax, and a
   LIVE deep link into the reference implementation. 20 rows ship: API keys with
   reveal-once secrets, team + invitations, projects/environments, the billing
   HUB (sub-pages as drills, never tabs), usage metering, rate limits, log
   stream, service health, security posture, data controls, asset library,
   playground, terminal, chat, realtime, integration hub, and the four report
   shapes (funnel, sources, revenue breakdown, forecast).
2. THE CATALOG AS DATA: patterns.json is GENERATED from that table and shipped
   in the npm files, so `stax-migrate patterns [query] [--json]` answers "what is
   the Stax reference for an API keys page?" mid-migration, printing the grammar
   and the link. An unknown screen exits 1 and sends the agent to the view
   grammar rather than guessing.
3. THE PROMPT KNOWS: M9 gains a PHASE 0.5 that reads both tables BEFORE mapping,
   with the rule "open the reference and copy its grammar, never improvise a
   pattern the framework already proves".

## VERIFY
- `stax-migrate patterns "api key"` prints the pfkeys grammar and its live link;
  `stax-migrate patterns "quantum teleporter"` exits 1 naming the view grammar;
  `--json` returns all 20.
- Every reference in patterns.json opens a real panel in the running app (drive
  them with playwright: 2+ panels and a named leaf on each).
- The catalog cannot drift: a test asserts every legacy label and every
  reference in patterns.json is present in the shipped spec template.
