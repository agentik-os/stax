# U-047: teach the audits what your framework is, without forking them

TARGET: {{TARGET}}
REFERENCE: `skills/staxaudit/STAX-LENS.md`

## DETECT

- Grep every forensic audit protocol you own for the name of your framework. If
  the count is zero, each of them is measuring a generic app and will report the
  framework's own contracts as defects.
- Run one on the app and read its top five findings. "Inconsistent spacing" on a
  layout fixed by contract, "add breadcrumbs" where a crumbbar already exists,
  "modal accessibility" in an app with no modals: each of those is attention
  spent on nothing, and it teaches the reader to skim the report.
- Ask the harder question: what does this audit MISS? A generic protocol cannot
  know the three assertions about your foot are all blind, because it does not
  know you have a foot.

## APPLY

1. ONE LENS, not N forks. A fork of every protocol duplicates the doctrine and
   rots the moment the framework moves. One file, referenced conditionally, is
   the only version that stays true.
2. THE DETECTOR FIRST. The lens must open with how an audit knows it applies,
   as a runnable command, and must say plainly what to do when it does not:
   run the normal protocol unchanged. Handle the half-adopted case explicitly,
   because it is BOTH and the report must say which surfaces are which.
3. WHAT TO STOP ASKING is half the value and the half nobody writes. List the
   findings that are true of the framework rather than the product, and say why
   each is not a defect here.
4. WHAT TO ASK INSTEAD, with the measurements. Include every case where the
   obvious assertion is blind, and say WHY it is blind: that is knowledge a
   generic protocol cannot derive and the reason the lens exists.
5. A PER-AUDIT TABLE naming what changes for each protocol. An a11y audit and a
   security audit need different things from the same framework.
6. INSERT THE POINTER after the frontmatter, so it is read before phase 1, and
   keep it to one conditional paragraph. A long insert is a fork with extra steps.

## VERIFY

- Grep the audits again: every one that should carry the pointer does.
- Run one audit against a NON-framework project and confirm the detector misses
  and the protocol runs unchanged. A lens that applies itself everywhere is worse
  than no lens.
- Run one against the framework app and check its findings changed: the
  framework-reporting noise is gone and at least one framework-specific defect
  class is now being probed.
- A test pins the lens contract, so a future edit cannot quietly drop the
  detector or the stop-asking list.
