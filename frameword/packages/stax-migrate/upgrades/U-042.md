# U-042: a manifest is not yet a design

TARGET: {{TARGET}}
REFERENCE: `stax-migrate shapes`, the Moonbase space in the reference app

## DETECT

- The conversion has a complete manifest: every screen carries a width, a head
  layout, a foot primary and a backend binding. Every contract is honoured.
- Open five domain panels and count the distinct BODY grammars. If the answer is
  one, the manifest was executed and nothing was designed. The reference case:
  213 panels, every contract correct, 1675 identical key/value rows.
- Grep the built surfaces for a repeated row class. A class used more than about
  200 times across unrelated domains is not a grammar, it is a default.

## APPLY

1. For each surface, write down the user's FIRST question in their words. Not
   "view invoices" but "which of these have not been paid".
2. Route that question through `stax-migrate shapes`. The catalog is keyed on
   what the data IS rather than what the screen was called, so an unfamiliar
   surface still routes.
3. Where nothing fits, build the shape and add it to the catalog with its
   anti-pattern. A shape without a stated anti-pattern is a menu item.
4. DERIVE every total, rate and verdict from the line items. A figure typed
   beside its own inputs disagrees with them on the first edit.
5. Colour from MEANING, never from the raw sign. A cost under plan is
   favourable while its delta is negative.

## VERIFY

- Count the distinct body grammars again on the same five panels. If the number
  did not move, the router was consulted and not obeyed: say so plainly rather
  than shipping.
- Every reference in the catalog opens a real, populated panel AND round-trips
  its URL (see U-041's gate).
- A test asserts that a figure shared by two panels is computed, not typed.
