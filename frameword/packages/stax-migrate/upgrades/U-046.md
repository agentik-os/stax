# U-046: the Stax audit, split so a phase cannot be faked

TARGET: {{TARGET}}
REFERENCE: `stax-migrate audit`, `skills/staxaudit/SKILL.md`

## DETECT

- The project has an audit protocol written as prose. Read three of its scored
  phases and look for a captured command run against THIS codebase. If a phase
  reasons plausibly and cites nothing, it is performative, and an agent will
  produce a hundred of them cheerfully.
- Count the PASS phases against the distinct real commands in the report. If
  passes outnumber commands, the audit asserted more than it ran.
- Look for a `fail` on a surface that was simply not running. An unreachable
  target scored as a law breach is the most damaging false finding an audit can
  produce: it slanders the app and hides that nobody looked at it.
- Look for a permanently red check that means nothing in this context. It trains
  every future reader to ignore the report.

## APPLY

1. SPLIT THE AUDIT. A mechanical half runs the real gates and records, per
   probe, the exact command, the exit code and the captured output into a JSON
   artefact. The forensic half reads that artefact. The split is what makes
   invariant 9 structural instead of aspirational.
2. THREE MODES, because a project is audited at three moments and each asks a
   different question: before the transfer (is it ready, what would be lost),
   during the build (does it obey its own laws), and continuously (do the
   declaration and the render still agree).
3. ONE HINGE PER MODE, named before any scoring, given ten times the scrutiny,
   and falsified: what would prove this is NOT the hinge? Run that check.
4. THREE READINGS THAT ARE NOT VERDICTS, and they must be distinguishable in the
   output: `pass`, `fail`, `unreachable` (an abort, no verdict), and
   `not applicable` (with the reason). Collapsing the last two into `fail` is
   how a report loses its reader.
5. THE DENSITY RULE. If PASS phases exceed distinct captured commands, cap
   confidence at medium regardless of score. Depth comes from more probes, never
   from more headings.
6. Pre-fix baseline before the first change, before-after matrix after the last,
   and no claim above 90 without it.

## VERIFY

- Point the audit at a target that is NOT running. It must report `unreachable`
  and say the word abort. If it reports `fail`, it will lie about every offline
  CI run forever.
- Point it at a project the probe does not apply to. It must say not applicable
  WITH the reason.
- Run it with no URL. Every gate needing one must be recorded as not run, never
  as a pass.
- Open the evidence file and confirm every probe carries its command and either
  real output or an explicit reason it produced none.
- Grep the finished report for a scored phase with no captured command. One is
  enough to fail the audit's own compliance.
