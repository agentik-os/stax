# U-040: URLs that read like paths a person could have guessed

TARGET: {{TARGET}}
REFERENCE: `frameword/packages/panels-core/src/index.ts` (SlugCodec, encodeLocation, decodeLocation)
and `frameword/apps/crm-specimen/src/slugs.ts` (a worked implementation)

## DETECT

- Open the app, drill two panels deep, and read the address bar out loud. If it
  contains the space name twice, a panel TYPE, or a namespace prefix
  (`#/pf-analytics/section~sec:pf-analytics/anblotter~an:blotter`), the URL is
  leaking internals that no visitor can parse.
- Count the characters. Fifty five to address two panels is a link nobody pastes.
- Grep for `encodeLocation(` with a single argument: the app is not supplying a
  codec, so it is publishing the engine's raw addressing.

## APPLY

1. THE ENGINE STAYS DOMAIN-FREE. Do not teach panels-core what "blotter" means.
   Add a `SlugCodec` interface and accept it as an OPTIONAL second argument on
   `encodeLocation` and `decodeLocation`:
   ```ts
   export interface SlugCodec {
     slug(target: PanelTarget, spaceId: string): string | null;
     target(slug: string, spaceId: string): PanelTarget | null;
     root?(spaceId: string): PanelTarget | null;
     spaceSlug?(spaceId: string): string | null;
     spaceId?(slug: string): string | null;
   }
   ```
   No codec means the existing `type~key` form, unchanged. That is what keeps
   this unit from being a breaking change.
2. THREAD IT THROUGH THE PROVIDER as a `slugCodec` prop, and pass it at all
   THREE decode sites (initial state, the async-adapter path, popstate) plus the
   single encode site. Missing one produces a URL that flickers between forms.
3. THE FOUR NAMING RULES, in the app's codec:
   - A space is named by its PUBLIC slug, not its internal id.
   - The space ROOT is never written: the space already implies it. Encode drops
     it, decode puts it back. This alone removes a whole segment from every URL.
   - A node's slug is its resource key with the namespace stripped.
   - On a collision the PUBLIC surface wins the bare word and the others keep
     their namespace. Rank the namespaces explicitly, do not rely on iteration
     order, or a shared link changes meaning between builds. A slug that is only
     digits is never awarded: `/1` addresses nothing a human can read.
4. THREE FORMS DECODE, AND THEY MIX inside one URL: a bare slug, an explicit
   `type~key` segment, and whatever legacy form already exists. Mixing has to be
   legal per-segment, because a runtime resource (a data row, a note created
   five seconds ago) is not in the static domain and MUST fall through.
5. DEGRADE, DO NOT FAIL. An unresolvable slug stops the walk and opens what did
   resolve. A renamed leaf then lands the visitor in the right space instead of
   on an empty screen.

## VERIFY

- Every public URL round-trips byte for byte: navigate to it, then assert
  `location.hash` equals what you typed. A URL that rewrites itself on load is
  a codec whose encode and decode disagree.
- THE BACKWARD-COMPATIBILITY PROOF IS THE OLD TEST SUITE. Run every pre-existing
  e2e test unchanged; they navigate with the old format, so a green suite is the
  evidence. Do not write a new "compat" test and call it proven.
- Assert that an old-format link NORMALISES: open the long form, then assert the
  address bar now holds the short one. A shared link should upgrade when clicked.
- Assert a mixed URL (one slug segment beside one `type~key` segment) resolves.
- Assert an unknown slug opens the space with zero page errors.
- Assert the collision rule on a real pair, and that a numeric key stayed
  qualified.
